## Code-quality assessment

### Git lease preservation and history

`scripts/git_lease_store.py:173–190, 203–227, 234–257, 267–296` reads the root regular-file entry through `ls-tree --full-tree -z`, validates mode/type/name, and decodes only the selected lease blob as JSON. Current, historical, invocation-ownership, and release-receipt readers share that validation. Symlink, directory, absent, and ambiguous lease entries cannot become a usable lease record merely because their object contents parse.

CAS obtains the authoritative expected commit, retains root neighboring entries as raw NUL-delimited bytes, replaces only `lease.json`, preserves the existing lease mode, and rebuilds a tree whose untouched entry modes, object IDs, filenames, and subtrees remain unchanged. Root-scoped traversal remains correct when the store's cwd is nested. Existing transition validation, immutable repository/source bindings, ownership capability, generation/history rules, parent ancestry, ordinary push, and final authoritative readback remain in the path. A stale proposal is rejected before its tree is published; a competing sibling proposal remains subject to ordinary fast-forward rejection.

`tests/test_git_lease_multidoc.py` exercises nested cwd, both root and nested lease names, neighboring executable/symlink/subtree entries, carriage-return/newline names, non-UTF-8 filename bytes, stale CAS, historical multi-document reads, and historical/current symlink rejection. The movement test in `tests/test_execution_lease.py:266–282` now injects the concurrent publication at the actual record-reading boundary and asserts the competing publication occurred. These assertions cover the behavior changed here instead of retaining an obsolete `git show` hook.

### Managed read-only admission and closure

The existing plan validator still forbids writer branches, declared worktrees, and write paths for nonwriters. `scripts/managed_host_bridge.py:170–176, 400–403` admits only the intended required single writer/read_only roles and rejects disabled reflog recording before dispatch. `scripts/managed_executor_runtime.py:239–250` creates the isolated detached checkout at the exact base and checks initial exact-base history before worker execution.

`scripts/managed_host_bridge.py:678–696` checks clean checkout, exact base HEAD, detached HEAD, enabled recording, present exact-base-only history, and unchanged remote source HEAD. It does not conflate clean final file bytes with proof that no intervening commit happened. Read-only completion requests a persisted checkpoint, retains real exact managed ownership, uses observe admission while recovering finalization, and supplies `result_commit=None` without invoking the source publisher. `scripts/managed_host_bridge.py:747–803` distinguishes successful read-only completion from failed-worker closure through the worker status, so lack of publication does not itself create a BLOCKED success or a false COMPLETE failure.

The draining/checkpointed/reconciled/ready release transitions remain exact-owner, exact-generation, exact-invocation transitions; checkpoint retries are bound to the persisted checkpoint. Release-history repair, supervisor quiescence, nonwriter pool acceptance, integration assessment, authoritative release-record readback, and final-response evaluation remain required. Session/request digests retain immutable role and attempt context. The four in-package finalization-interruption regressions cover pre-release states, and the independent narrow probe below covers the post-release interruption boundaries and failed read-only closure.

These are cooperative integrity checks, as the specification expressly states. This review does not claim an adversarial Git sandbox or enforcement against deliberate manipulation of Git internals/history records.

Recovery does not restore a gate callback or treat the journal as new authority.
