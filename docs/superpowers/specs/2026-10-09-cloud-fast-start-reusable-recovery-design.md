## Architecture and interfaces

New deterministic modules prepare and assess data. They never issue a lease, a provider permission, a scheduler permission or an alternative submission identity. Existing transports own durable operation journals; managed_host_bridge and execution_lease_v2 remain execution authority. Existing routers select a backend. Existing submission_recovery reconciles uncertain effects.

| Interface | Exact signature / result | Authority boundary |
| --- | --- | --- |
| existing capability_router | route(registry, request, now_utc) | Capability selection; readiness is observed, not granted |
| existing cost_router | route(registry, request, policy, context, now_utc) | Cloud preference and machine-valid expensive exception |
| existing recovery_recipes | validate_catalog(c); validate_diagnosis(d); select(c, d) | Allowlisted deterministic recommendations; all authority flags false |
| existing resume_capsule | validate(c); assess(capsule, probe, max_age_seconds=7200) | Fresh complete probe required for resume |
| existing CodexCloudCLI | __init__(journal_root, executable='codex', runner=None, max_pages=1000); submit(request, *, launch_authorized); observe(operation_key); ingest_report(operation_key, report, evidence_ref) | COMPUTE_ONLY transport owns journal, exact callback and report binding |
| existing CodexCloudDevelopment | submit(request, *, launch_authorized); observe(operation_key); export_diff(operation_key, *, evidence_root) | Development transport owns journal and exported content/tree binding |
| NEW codex_cloud_profile | validate_profile(profile); assess_profile(profile, probe, now_utc, *, max_age_seconds=300) | Pure strict validation and binding-specific capability qualification |
| NEW codex_cloud_entrypoint | prepare(profile, context, probe, registry, routing_policy, routing_context, now_utc); submit(prepared, transport, *, launch_authorized); observe(operation_key, transport); intake(operation_key, payload, evidence_ref, transport, *, evidence_root=None) | Delegates to exact existing transport; never submits in prepare/observe/intake |
| recipe v2 extension | select(catalog, diagnosis, *, bindings=None, now_utc=None) | v1 behavior remains supported; v2 requires verified provenance/freshness |

New APIs accept JSON-compatible dicts; validators return their validated argument or raise ValueError. assess_profile returns {status: READY|PARTIAL|UNKNOWN|STALE, modes: map, reasons: list, profile_digest: sha256, authorizes_external_start: false}. prepare returns cloud-entrypoint-preparation/v1 with action CONTINUE_NATIVE|OBSERVE_EXISTING|READY_FOR_SUBMIT|BLOCKED, exact mode/request/operation_key or null, stable binding digest, observation references, reasons, next_action and all authority flags false. submit accepts only READY_FOR_SUBMIT, revalidates exact bindings and delegates unchanged request to one qualified transport with its original callable. CONTINUE_NATIVE is a local-work recommendation, never a remote submit operation. intake delegates COMPUTE_ONLY to ingest_report and DEVELOPMENT to export_diff; exact modes cannot be confused. Validation/intake errors remain typed failures, not synthetic successful provider tasks.

Entry CLI is python -B scripts/codex_cloud_entrypoint.py prepare --profile FILE --context FILE --probe FILE --registry FILE --policy FILE --routing-context FILE --now UTC; observe --operation-key KEY --journal-root DIR --mode MODE; intake --operation-key KEY --journal-root DIR --mode MODE --report FILE --evidence-ref REF [--evidence-root DIR]. Submit remains a Python API requiring the real launch callback; an unauthenticated CLI submit flag cannot fabricate it. No arbitrary shell recipe runner is added.

## Stable profile and dynamic observations

Stable project profile is outside immutable core at docs/cdc-cloud-profile.json. A packaged template is templates/codex-cloud-profile.json, initially unknown/unqualified. Schema codex-cloud-project-profile/v1 has exactly: schema, repository, source_ref, environment {id, url}, control_host {kind, binding_ref}, access_modes {native_runtime, official_ui, official_cli}, toolchain {cli_executable, cli_version}, setup {fingerprint, commands}, policy_digest, provenance. Each access-mode entry has configured:boolean, capability_ref:string|null; unknown IDs/URLs/version stay null. setup.commands is list[list[string]] preserving argument bytes; no shell interpolation/trim. Provenance entries bind profile field/group, evidence_ref, evidence_sha256 and qualification time. HTTPS URLs and repository identities must match approved public host families; reject credential-bearing URLs, secret/token/password/private-key fields and unrecognized fields. A profile stores references, not credentials or complete environment.

Dynamic schema cloud-profile-probe/v1: observed_at_utc, complete, repository, source_ref, environment_id, setup_fingerprint, policy_digest, cli_version, access_modes. Mode observations have status ready|unavailable|unknown, reason, evidence_ref, binding_digest. Current task/journal/health stay outside stable profile. Changing repository/environment/policy/setup invalidates all affected qualifications; changing CLI version invalidates CLI only. Future/stale/incomplete probes cannot authorize readiness. Native mode requires authenticated current runtime binding; UI mode requires actual supported UI task/result evidence; CLI mode requires actual version and supported successful capability observation. CLI401 invalidates CLI, preserves separately verified native access, and never enables Codespace fallback. No private HTTP discovery, credential copying, blanket dependency reinstall or automatic auth repair.

## Entry lifecycle and operation recovery

Load stable profile, dynamic probe, existing task/operation journal and resume capsule first. Any known active/submitting/unknown operation returns OBSERVE_EXISTING using the SAME exact operation key/task/guard. Incomplete inventory remains unknown. Lost submit response never permits a replacement key or a second submit. For new work, prepare exact request through existing contract validators and router policies. Preflight never starts a provider. Immediately before a real effect, fresh source/lease/intent/budget/guard/action callback must still pass existing released runtime gates. Profile qualification is reusable setup evidence, not a cached lease or one-use claim.

A Codespace create/resume decision requires explicit machine-valid exception fields reason, current evidence reference/binding/time and allowed budget. Missing CLI, transient Cloud transport error or unfamiliar entrypoint alone fail this predicate. Existing allowed control hosts may be used; this feature cannot create one by default. A portable task retains its required platform/release CI gates even when routed to native Cloud.
