# CDC 2.11.6: coordination preservation and Cloud execution

Owner-authorized maintenance patch under released CDC 2.11.5. Minimum supported runtime remains 2.11.3. Canonical source is bajoicheg/g-cdc. Schedulers remain owner-paused.

## Coordination store

GitLeaseStore replaces only the root regular-file lease.json entry. Preserve every neighboring entry, object ID, mode, and subtree from the exact expected coordination commit. Read current and historical leases from multi-document trees; reject symlink, directory, missing or ambiguous lease entries. Preserve existing schema, ownership, generation, ancestry, and ordinary fast-forward CAS gates. A competing update must reject the stale proposal without deleting its documents.

## Managed host read-only execution

The existing managed-host/v1 contract accepts one required writer or read_only task. A read_only task has no branch, declared worktree or write paths. Runtime creates an isolated detached checkout at the plan base. Success requires unchanged clean checkout and unchanged source ref, plus the requested output/evidence refs. Never publish or invent a result commit for read_only success. Still acquire a real managed invocation capability, transactionally release its lease, accept a nonwriter pool result, and pass the final-response gate. Retry/recovery must retain the same immutable role and attempt.

Admit read_only execution only with enabled reflog recording and observed initial exact-base history. An absent or changed history cannot prove success. These cooperative checks do not provide an adversarial Git sandbox.

## Native Cloud adapter

Use the supported authenticated Codex CLI, argument arrays, one attempt and an explicit environment ID/label/source branch/SHA. No credential reads or private HTTP API. Durable submission state precedes the single exec call; reconnect never repeats exec for an attempted operation. External ownership, budget, intent and one-use claim remain caller requirements. Journal is a conservative recovery aid, never a substitute for those gates.

Use cloud list --json with complete cursor pagination and local environment filtering because CLI 0.160.0 may ignore --env. Recover an unknown submission only from one exact operation/attempt marker with matching environment; ambiguity/incomplete inventory remain unknown. READY alone means waiting_report. Accept a host-observed provider report only with matching task/environment/operation/attempt/repository, clean unchanged exact source SHA, exact planned command arrays, observed exit codes and log digests. Record a failed verification as failed. CLI has no supported machine report export: host report ingestion is explicit and never guessed from READY.

Owner preference: Codex Cloud is primary for eligible portable CDC compute, including public repositories. Cost routing must retain that preference ahead of unmetered Actions; transient failure means recover/wait. Required platform/release CI remains a separate gate. Existing policies lacking the new explicit preference retain backward-compatible routing.

## Observed native Cloud preflight correction

The submitting host independently verifies the canonical repository/environment association and exact remote source branch SHA. A provider checkout may have no Git remotes; missing origin alone is not conflicting identity. Inspect any available identity without changing Git configuration, reject conflicting configured remotes, and distinguish host-bound values from independent provider observations. An exact-task result=NOT_RUN with checks=[] is failed even on an unchanged clean SHA. NOT_RUN with command evidence is rejected, and explicit repository_identity_status=MISMATCH cannot pass matching checks. Preserve the actual initial NOT_RUN report, original charged start and failure circuit; any repeat needs concrete reviewed correction and remaining budget.
