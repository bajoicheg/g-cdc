# CDC Telegram project operations

One VPS hub, explicit project and exact Codex chat for every human prompt. Existing owner route @CDC_VPS_bot → @VVP_2017; numeric owner/chat identities, root-only credentials, no new public network listener. Projects bind existing saved VPS directories. Existing chats come from native thread/list and their cwd is validated before turn/start. Prompt text is sent unchanged as real user input, with original Telegram update/message IDs retained. /new is the only automatic thread creation path; /chats selection never starts a model.

Commands: /projects, /chats g-cdc, /task g-cdc <prompt>, /new g-cdc <prompt>, /status [project]. Reply to a bound card targets that exact project/chat. Pause/cancel interrupts the exact native thread/turn and does not undo changes. Resume continues the same paused task with original ID, attempts and UNKNOWN spent retained. UNKNOWN effects are not replayed. Native permissions, model, account and settings are inherited, never widened. Kimi disabled; old Fleet/Supervisor loops remain paused.

Notifications show colored project/headline, short consequence, Moscow time and contextual buttons. Native completion is separate from deployment/canonical release success. No model calls for polling, project/chat choice, details, status or pause/cancel. Work starts only from an owner prompt or resume. The deterministic watcher observes only submitted IDs and stops after repeated unavailable observations; history is never scanned into model context.

Every ship uses client.py or /usr/local/bin/cdc-telegram: required project_id, ship_id, event_id, status (green/red/yellow), title; optional text, details, task_id/thread_id/turn_id. Unknown projects are refused; event IDs suppress duplicates; uncertain sends stay UNKNOWN. Unix peer UIDs include registered VPS participants, excluding Kimi. Ships never receive the token. Remote clients can use an already authorized SSH alias with --ssh; JSON goes over stdin, never interpolated in a remote shell. Windows/client deployment remains UNKNOWN.

Fleet is the registry and cross-project assessment/planning layer, not a super-writer. Project leases, Source refs, roles and budgets stay native CDC responsibilities. This is a VPS operator integration, not a new canonical SDK release.
